# Сравнительный анализ и стратегия выбора датасета для исследования

Документ подготовлен в рамках исследовательской работы:
> **«Качество скана и устойчивость OCR/KIE к деградациям»**

---

## 1. Цели и исследовательские требования к датасету

Экспериментальная цепочка проекта имеет вид:
```text
Исходный документ (Image + OCR GT + KIE GT)
         ↓
Генерация синтетической деградации (Severity 0..4, fixed seed)
         ↓
Предварительная обработка (Preprocessing / Enhancement)
         ↓
OCR Engine (Извлечение токенов и координат)
         ↓
KIE Engine (Семантическое извлечение ключевых полей)
         ↓
Evaluation (CER, WER, Field F1, Document Exact Match)
```

Для корректной и воспроизводимой валидации датасет обязан одновременно удовлетворять следующим требованиям:
1. **Наличие исходных растровых изображений документов** в исходном качестве (сканы или четкие фотографии документов без предварительно наложенных искажений).
2. **Полноценный Ground Truth для OCR**: эталонная транскрипция текста документа (построчная или пословная с ограничивающими рамками), позволяющая вычислять Character Error Rate (CER) и Word Error Rate (WER).
3. **Структурированный Ground Truth для KIE**: семантическая разметка ключевых атрибутов документа (название организации/продавца, дата, итоговая сумма, адрес) для вычисления Precision, Recall, Field F1 и Document Exact Match.
4. **Возможность попиксельного наложения синтетических деградаций**: изображения должны быть в формате растровой графики (RGB/Grayscale `uint8`), допускающем применение фильтров OpenCV/SciPy (размытие, шум, сжатие, перспективные искажения, тени).
5. **Статистически достаточный объем выборки**: не менее 50–100 документов в тестовом сплите для получения статистически значимых выводов без перегрузки квот GPU на Kaggle.
6. **Доступность на платформе Kaggle**: возможность беспрепятственного подключения через Kaggle Datasets API без закрытых лицензий или сложных процедур ручной авторизации.

## 2. Кандидаты на исследование

В качестве кандидатов детально исследованы 4 признанных бенчмарка в области Document AI:
1. **SROIE** (Scanned Receipts OCR and Information Extraction, ICDAR 2019).
2. **FUNSD** (Form Understanding in Noisy Scanned Documents, ICDAR-OST 2019).
3. **CORD** (Consolidated Receipt Dataset for Post-OCR Parsing, Clova AI / NeurIPS 2019).
4. **WildReceipt** (Large-Scale Receipt Dataset for KIE, Pattern Recognition Letters 2021).

Дополнительно рассмотрены, но исключены из детального рассмотрения:
* *DocVQA*: ориентирован на свободный вопрос-ответ (VQA), отсутствует фиксированная схема ключевых полей.
* *Kleister-NDA*: многостраничные юридические PDF-документы (в среднем 3.8 страницы на документ), что в разы увеличивает вычислительную сложность и смещает фокус с качества скана отдельной страницы на поиск по тексту документа.
* *RVL-CDIP*: разметка только на уровне классификации категории документа (16 классов), отсутствует разметка текста и KIE.

## 4. Оценка по критериям исследования (C1 – C8)

### C1 — OCR Ground Truth (Эталонный текст для CER/WER)
* **SROIE:** Полная построчная разметка всех текстовых блоков документа с координатами. Позволяет собрать канонический текст документа через сортировку строк в порядке чтения (reading order: сверху-вниз, слева-направо).
* **FUNSD:** Пословная разметка, сгруппированная в блоки. Очень точный OCR GT.
* **CORD:** Пословная и построчная разметка в формате JSON.
* **WildReceipt:** Построчная разметка в JSON lines.

### C2 — KIE Ground Truth (Структурированная разметка полей)
* **SROIE:** Канонический JSON с 4 ключевыми полями на документ: `company` (название поставщика), `date` (дата операции), `address` (адрес), `total` (итоговая сумма к оплате). Идеально подходит для оценки как эвристических (regex), так и ML-моделей.
* **FUNSD:** Разметка классов блоков (`question`, `answer`, `header`) и ребер графа (связи вопрос-ответ). Не имеет фиксированных именованных сущностей (нет поля "итого" или "дата", есть пара "ключ-значение").
* **CORD:** 30 вложенных категорий (`menu.nm`, `menu.price`, `total.total_price`). Слишком детализировано для базового исследования влияния деградаций.
* **WildReceipt:** 25 категорий ключевых полей.

### C3 — Image Availability (Наличие качественных исходных изображений)
* **SROIE:** 987 исходных RGB изображений высокого разрешения (.jpg), четкие сканы и фотографии реальных чеков.
* **FUNSD:** 199 полутоновых сканов старых бланков. Уже содержат естественный исторический шум, что затрудняет эксперимент с baseline severity=0 (оригинал уже искажен).
* **CORD:** 1,000 четких фотографий чеков.
* **WildReceipt:** 1,765 изображений различного качества.

### C4 — Reproducible Degradation (Применимость синтетических деградаций)
* Все 4 датасета предоставляют растровые изображения (JPG/PNG), пригодные для попиксельных манипуляций OpenCV (размытие, аддитивный гауссов шум, сжатие JPEG, геометрические сдвиги, маски теней).

### C5 — Dataset Size (Объем выборки и вычислительные затраты)
* **SROIE:** 361 тестовое изображение. При матрице экспериментов (9 типов деградаций $\times$ 4 severity + clean = 37 состояний) на выборке из 100 тестовых документов получаем 3,700 инференсов OCR. Это идеально вписывается в лимит времени Kaggle GPU (около 20–35 минут).
* **FUNSD:** Всего 50 тестовых документов. Выборка слишком мала для надежных статистических распределений метрик.
* **CORD:** 100 тестовых документов. Хороший размер, но индонезийский язык усложняет интерпретацию ошибок.
* **WildReceipt:** 500 тестовых документов. Достаточный объем.

### C6 — Annotation Quality (Пригодность разметки для автоматической оценки)
* **SROIE:** Разметка Task 3 представляет собой строгий JSON словарь `{"company": "...", "date": "...", "address": "...", "total": "..."}`. Это позволяет однозначно реализовать детерминированную нормализацию (приведение дат к ISO, очистка валют до float) и прямое вычисление Exact Match / F1.
* **FUNSD:** Оценка требует графового сопоставления связей между сущностями (entity linking F1), что вносит сторонний шум модели связывания.
* **CORD:** Иерархический JSON требует сложного маппинга множественных позиций меню.

### C7 — Computational Feasibility (Вычислительная доступность на Kaggle)
* **SROIE:** Датасет уже опубликован на Kaggle (например, `urbikn/sroie-datasetv2`) и монтируется к ядру в один клик. Объем ~120 МБ скачивается за секунды.
* **FUNSD / CORD / WildReceipt:** Требуют загрузки через HuggingFace `datasets` или сторонние скрипты, что может вызывать проблемы в закрытых Kaggle-окружениях без доступа в сеть.

### C8 — Research Relevance (Соответствие дипломной теме)
* Тема диплома: «Качество скана и устойчивость OCR/KIE к деградациям».
* Чеки и счета (SROIE) — наиболее массовый прикладной тип документов, подверженный деградациям при сканировании и мобильной съёмке (смятие, выцветание термопечати, смаз камеры, тени, геометрический перекос). Извлечение даты и суммы — классическая промышленная задача KIE.

## 5. Детальный аудит SROIE

1. **Доступные файлы аннотаций:**
   * Каждому изображению `XXXXX.jpg` соответствуют:
     * `XXXXX.txt` (Task 1 & 2): строки вида `x1,y1,x2,y2,x3,y3,x4,y4,transcription`.
     * `XXXXX.json` (Task 3): словарь вида:
       ```json
       {
         "company": "BOOK TA CO. / KINOKUNIYA BOOK STORES",
         "date": "27/12/2017",
         "address": "LOT 406-408 & 429-430, LEVEL 4, SURIA KLCC, 50088 KUALA LUMPUR",
         "total": "4.50"
       }
       ```
2. **Формирование полноценного OCR Ground Truth:**
   * Текстовые строки сортируются по вертикальной координате $y_{min}$, затем по горизонтальной $x_{min}$ (с допуском на строку $\Delta y$).
   * Полный текст формируется конкатенацией через `\n`.
   * Из 8 координат полигона вычисляется охватывающий `BoundingBox(x_min, y_min, x_max, y_max)`.
3. **Формирование KIE Ground Truth:**
   * Прямое отображение ключей JSON в объект `KIEGroundTruth(document_id, fields)`.
   * Значения полей нормализуются согласно правилам `ADR-005` (приведение дат, сумм, удаление лишних пробелов).
4. **Характер документов (сканы vs фото):**
   * Датасет содержит смесь планшетных сканов и фотографий кассовых чеков. Это предоставляет идеальный баланс: ровные сканы служат базовой точкой (Clean baseline severity=0), а фотографии содержат естественные перспективные наклоны.
5. **Применимость синтетических деградаций:**
   * На изображения SROIE отлично ложатся:
     * Gaussian Blur и Motion Blur (имитация расфокусировки и движения сканера/камеры);
     * Gaussian Noise (шум сенсора);
     * JPEG compression artifacts (артефакты сжатия при пересылке);
     * Downsampling / Low DPI (сканирование с низким разрешением 72–150 DPI);
     * Non-uniform illumination / Shadows (затенение угла листа при сканировании или съемке);
     * Skew / Rotation (перекос листа на стекле сканера).
6. **Лицензионная чистота:**
   * Опубликован в рамках академического состязания ICDAR 2019 под открытой исследовательской лицензией, разрешающей некоммерческое использование и цитирование в публикациях и дипломных работах.

## 6. Детальный аудит альтернатив

### FUNSD (Form Understanding in Noisy Scanned Documents)
* **Плюсы:** Настоящие исторические сканы форм (анкеты, таблицы, отчеты), отличная пословная разметка.
* **Минусы для нашей темы:**
  1. Тестовый сплит содержит всего 50 документов, что не позволяет сформировать репрезентативные подвыборки.
  2. Исходные сканы уже содержат сильный шум сканирования 1970–90-х годов, факсимильные артефакты и просвечивающий текст. Невозможно замерить «чистый базовый уровень» (severity=0 уже зашумлен).
  3. KIE сформулирован как задача классификации сущностей (`question`/`answer`) и построения графа связей, а не извлечения целевых полей документа.

### CORD (Consolidated Receipt Dataset for Post-OCR Parsing)
* **Плюсы:** 1000 чеков, высокое качество разметки Clova AI.
* **Минусы для нашей темы:**
  1. Язык документов — индонезийский (Bahasa Indonesia). Это затрудняет качественную оценку OCR общедоступными моделями и усложняет написание baseline-эвристик (regex для дат, месяцев, сумм).
  2. Иерархия из 30 подкатегорий избыточна и смещает исследование в сторону парсинга сложных таблиц и меню, а не влияния качества скана на базовую устойчивость.

### WildReceipt
* **Плюсы:** Большой объем (1,765 чеков), хорошая разметка.
* **Минусы для нашей темы:**
  1. Отсутствует официальный встроенный датасет на Kaggle (требуется ручная загрузка или скачивание через китайские репозитории OpenDataLab).
  2. Разнородный мультиязычный состав (включая китайские иероглифы).

## 7. РЕКОМЕНДОВАННЫЙ ДАТАСЕТ (RECOMMENDED DATASET)

> **Рекомендованный датасет:** **SROIE (ICDAR 2019 Robust Reading Challenge on Scanned Receipts)**.

### Фактическое обоснование:
1. **Идеальное соответствие целевому пайплайну:** наличие независимой, подтвержденной разметки как для полного OCR (построчный текст и полигоны), так и для KIE (ключи `company`, `date`, `address`, `total`).
2. **Языковая доступность:** английский язык документов обеспечивает максимальную точность современных открытых OCR-движков (PaddleOCR, Tesseract) без необходимости дообучения под редкие языки.
3. **Статистическая надежность:** 361 документ в тестовом сплите позволяет выделить сбалансированные подвыборки:
   * *Smoke test:* 5 документов;
   * *Development / Calibration:* 25 документов;
   * *Main Research Experiment:* 100 тестовых документов.
4. **Инфраструктурная готовность на Kaggle:** датасет присутствует в публичном реестре Kaggle Datasets (`urbikn/sroie-datasetv2`), что позволяет запускать вычисления на Kaggle GPU в пакетном режиме без риска прерывания по загрузке данных.

## 8. Универсальный контракт и архитектура адаптеров (Dataset Adapter Architecture)

Для обеспечения расширяемости системы в будущем проектируется слой абстракции датасета.

```text
               BaseDatasetAdapter (Абстрактный контракт)
                         ▲
                         │
        ┌────────────────┼────────────────┐
        │                                 │
   SROIEAdapter                     CORDAdapter (Опционально)
```

### Контракт `BaseDatasetAdapter`:
```python
from abc import ABC, abstractmethod
from typing import List, Optional
import numpy as np
from src.core.schemas import DocumentMetadata, OCRGroundTruth, KIEGroundTruth

class BaseDatasetAdapter(ABC):
    """Абстрактный интерфейс для загрузки и адаптации произвольного датасета."""

    @abstractmethod
    def list_document_ids(self, split: str = "test") -> List[str]:
        """Возвращает список идентификаторов документов для указанного сплита."""
        pass

    @abstractmethod
    def get_metadata(self, document_id: str) -> DocumentMetadata:
        """Возвращает типизированные метаданные документа (размеры, путь, сплит)."""
        pass

    @abstractmethod
    def get_image(self, document_id: str) -> np.ndarray:
        """Загружает исходное изображение документа в виде numpy ndarray (H, W, 3)."""
        pass

    @abstractmethod
    def get_ocr_ground_truth(self, document_id: str) -> OCRGroundTruth:
        """Возвращает эталонный текст и токены для оценки качества OCR."""
        pass

    @abstractmethod
    def get_kie_ground_truth(self, document_id: str) -> KIEGroundTruth:
        """Возвращает эталонные семантические поля для оценки качества KIE."""
        pass
```

### Преимущества и Trade-offs архитектуры адаптеров:
* **Плюсы:**
  * Код деградаций, OCR, KIE и экспериментов полностью отвязан от структуры файлов SROIE.
  * При необходимости добавить русскоязычный датасет или CORD достаточно написать один класс-адаптер без изменения остального пайплайна.
* **Trade-offs:**
  * Небольшое количество начального шаблонного кода (boilerplate) для реализации адаптера.

## 9. Предотвращение Data Leakage

При проведении экспериментов с синтетическими деградациями существует высокий риск методических ошибок и утечек данных (Data Leakage):

1. **Риск 1: Применение деградации до разделения на сплиты (Pre-split degradation leakage).**
   * *Угроза:* Если аугментировать весь массив изображений, а затем случайно разбить на train/test, различные деградированные версии одного и того же физического чека окажутся и в train, и в test.
   * *Защита:* **Правило разделения:** Разбиение на `train`, `validation` и `test` строго фиксируется на уровне уникального `document_id` исходных документов.
2. **Риск 2: Подбор параметров препроцессинга на тестовом сплите (Hyperparameter tuning leakage).**
   * *Угроза:* Настройка порогов бинаризации Sauvola или параметров фильтров денойзинга под 100 тестовых изображений приводит к завышению робастности.
   * *Защита:* Все параметры алгоритмов улучшения (enhancement) калибруются исключительно на `validation` сплите (25 документов). На `test` сплите запускается фиксированный алгоритм без донастройки.
3. **Риск 3: Утечка через глобальные метаданные (Metadata leakage).**
   * *Угроза:* Передача истинных координат или текста в модуль KIE в обход вывода OCR.
   * *Защита:* Модуль KIE получает на вход **исключительно** объект `OCRResult`, сгенерированный OCR-движком.

## 10. Экспериментальные подвыборки (Experiment Subsets)

Для оптимизации времени разработки и вычислительных ресурсов зафиксированы три гранулярные выборки из SROIE:

1. **Smoke Test Subset ($N = 3..5$ документов):**
   * *Назначение:* Локальный автоматизированный smoke-тест пайплайна в CI/CD и unit-тестах.
   * *Формат:* Хранится локально в `data/sample/` (синтетические/фикстурные файлы малого размера).
   * *Время прогона:* $< 5$ секунд на CPU.
2. **Development / Calibration Subset ($N = 25$ документов из train сплита):**
   * *Назначение:* Локальная отладка генераторов деградаций, визуальная калибровка параметров severity 1..4, подбор параметров препроцессинга.
   * *Время прогона:* $< 2$ минут на CPU.
